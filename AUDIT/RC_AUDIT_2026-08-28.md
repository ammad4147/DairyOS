## Release-candidate architecture observations

### Blocking

1. **Desktop spec portability** — the historical `D:/DairyOS` machine-specific paths were a packaging defect. The RC spec now derives paths from `SPECPATH`.
2. **Private PostgreSQL packaging contract** — the Windows supervisor expects `runtime/PostgreSQL` beside the frozen executable. The RC spec must package this runtime; the RC build gate explicitly verifies `runtime/PostgreSQL/bin/postgres.exe` and executes `postgres.exe --version`.
3. **Installer evidence** — the authoritative acceptance matrix supports a Windows installer, not merely a PyInstaller directory bundle. A Release cannot be declared until an actual installer is built and exercised.
4. **Lifecycle evidence** — clean install, zero state, populated upgrade, uninstall/reinstall preservation, reboot recovery, backup/restore, production contamination, and supported hardware evidence require an actual Windows test environment. CI source success cannot substitute for this evidence.

### Non-blocking architectural debt

1. `dairyos.herd.dashboard` contains a legacy Python dashboard package with stale `from src.dairyos...` imports. The current UI is React-based; the legacy package should eventually be removed or migrated, but it is excluded from the RC bundle rather than changing the live UI.
2. The RC frontend build reports a >500 kB minified JavaScript chunk. This is a performance optimization item, not an acceptance blocker for the current release.
3. Some transaction boundaries are still shared between repositories and endpoint/service layers via `commit=False`. A dedicated Unit-of-Work boundary would improve architectural clarity in a later phase.
4. Milk reconciliation currently combines trend-intelligence retrieval with production-repository inspection in one service. A dedicated production-basis provider would reduce coupling in a later phase.

## UI boundary

No Dashboard or tab layout changes are authorized or included. The supported navigation remains the existing nine tabs.

## Release decision

Source-level certification is **PASS**. Windows Desktop bundle packaging is **PASS only after the RC packaging contract is proven by the new build gate**. Final Release remains **BLOCKED** until the authoritative Windows installer acceptance matrix is fully evidenced on a real Windows deployment target.
